Scope: the imperative app-window Reopen click listener plus every explicit JSX `onClick` / `onSubmit` binding in production TSX under `packages/app/src` and `packages/ui/src`, traced through owned callbacks, mutation functions and terminal effects. Native form submit buttons are covered by their form handler. Props forwarded by reusable components are recorded at both the binding and the owning callback. No installer/bridge changes. Sources not owning these bindings (queries, polling, effects, keyboard primitives) are not silently represented as click handlers.

The fixed idiom is pending commit → two animation frames → work. Local state uses `paintPending` (`flushSync` plus the barrier); query mutations await the same barrier from `onMutate` after their pending notification. Background documents use a non-paint fallback and do not claim visible acknowledgment. A visibility change releases a suspended frame wait. Initial bootstrap effects keep their original lifecycle; only retry clicks add the barrier.

Paint-yield fixes acknowledgment ordering only; async-arrival geometry is NOT claimed. GLA-340 owns unknown-cardinality/empty/error/auth/VM/workload/credential arrival reservation. GLA-335 owns shell header/nav reservation; app-shell.tsx is unchanged. GLA-338 owns absent pending UI and clipboard constraints; GLA-339 owns query retry/refetch ordering.

## Additional owning callbacks

Package/deploy callbacks in `pages/apps/deploy.tsx`: `onPickFolder`, `onPickRecent`, `pickFolderForCloud` (cloud pre-fire picker), `runDeploy` (package/upload/deploy), `runCloudDeploy` (bundled CLI), `confirmCloudDeploy`, `selectTarget`, `startRuntime`, plus retry delegates. All existing pending barriers are fixed; agent readiness and the human deploy action remain independent. `fetchKnownCloudEnvs` is best-effort background enrichment after the review opens, not a click gate. The cloud review confirmation still precedes deployment.

Publisher/grant dialog continuations delegate to `installSource`, `openApp`, or catalogue `acceptUnknown`; no trust decision moved. Confirmation-dialog promises intentionally await the human decision, not backend work, so busy begins only after acceptance.

Terminal session creation/removal updates the provider's local session list before its effects allocate/dispose the PTY. Read callbacks shared by Retry and polling are deferred explicitly rather than changing all background polling semantics.
