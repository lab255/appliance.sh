# Desktop information architecture

The desktop app has user and developer modes. Both modes keep the workspace
switcher, app-mode control, and Settings access in the shared shell. Navigation
is generated by `packages/app/src/lib/app-navigation.ts`; routes are defined in
`packages/app/src/router/routes.tsx`.

## User mode

User mode opens at **Installed Apps** and shows three navigation items:

- **Installed Apps** (`/apps`) lists apps for the selected workspace. Users can
  search, install a local bundle, open or stop apps, and see the command for
  app logs.
- **Catalogue** (`/catalogue`) shows the verified signed index with search,
  category filters, freshness status, and install controls.
- **Settings** (`/settings`) contains mode selection, team access when
  available, updates, preferences, entitlement review, and build information.

## Developer mode

Developer mode includes Installed Apps, Catalogue, and Settings, plus these
surfaces when the current host and key role support them:

- **Setup** (`/setup`) connects to an installation or prepares a local machine.
  It is emphasized while an operator has no configured target.
- **Projects** (`/projects`) lists projects and recent activity. Deploy from
  `/projects/deploy`; project and environment details use nested routes.
- **Agents** (`/agents`) lists and starts coding-agent sessions on desktop hosts
  with a managed VM.
- **Machine** (`/machine`) shows local VM lifecycle, runtime details, workloads,
  egress controls, credential rules, and diagnostics.
- **Cloud** (`/cloud`) lists connected cloud installations. Installation setup
  uses `/cloud/bootstrap` and `/cloud/bootstrap/run`; detail uses `/cloud/:id`.

Operator-only screens are hidden for member keys and are also guarded at the
route level. The API server remains the authorization boundary.

## Shared shell behavior

The terminal dock and terminal-session provider sit outside the route outlet,
so shell and agent terminals stay mounted while users navigate. The workspace
switcher selects the local machine or a configured cloud target and updates the
data shown by workspace-aware pages, including Installed Apps.

Standalone invite and setup-complete pages do not render the app shell. All
other primary pages render inside it.

## Routes

| Route                                   | Screen                          |
| --------------------------------------- | ------------------------------- |
| `/apps`                                 | Installed Apps                  |
| `/catalogue`                            | Catalogue                       |
| `/setup`                                | Setup                           |
| `/setup/connect`                        | Connect                         |
| `/setup/doctor`                         | Local prerequisites             |
| `/projects`                             | Projects                        |
| `/projects/deploy`                      | Deploy                          |
| `/projects/:id`                         | Project detail                  |
| `/projects/:projectId/environments/:id` | Environment detail              |
| `/agents`                               | Agents                          |
| `/machine`                              | Local machine                   |
| `/cloud`                                | Cloud installations             |
| `/cloud/bootstrap`                      | Cloud installation setup        |
| `/cloud/bootstrap/run`                  | Cloud installation progress     |
| `/cloud/:id`                            | Cloud installation detail       |
| `/settings`                             | Settings                        |
| `/deployments` and `/deployments/:id`   | Deployment list and detail      |
| `/invite` and `/setup-complete`         | Standalone access/setup screens |

Older deep links redirect to their current equivalents: `/dashboard` to
`/projects`, `/connect` to `/setup/connect`, `/clusters` to `/machine`,
`/bootstrap` to `/cloud/bootstrap`, `/local-runtime` to `/machine`, and
`/local-runtime/deploy` to `/projects/deploy`. Query parameters used by setup
and deploy flows are preserved by these redirects.
