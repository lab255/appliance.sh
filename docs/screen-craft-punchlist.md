# Screen craft punch list — desktop app

1. Standardize three composition rails: `max-w-5xl` browse screens, `max-w-3xl` detail/management screens, and centered `max-w-2xl` focused setup tasks.
2. Make every state readable without color: pair the existing dot with a persistent text label, and announce changing status and streamed output without flooding assistive technology.
3. Give every custom control a visible `focus-visible` ring on true black, complete keyboard behavior, and predictable focus return after menus, drawers, and dialogs close.
4. Unify consequential actions: contextual inline confirmation for resets/forgetting, a standard confirm dialog for deletion/removal, and type-the-name plus a final dialog only for cloud destruction.
5. Apply one calm product voice: plain outcome first, honest duration and leave-safety, technical language behind **Technical details**, and the binding terms **Sandbox**, **App hosting**, and **Set up hosting**.

## Scope and implementation order

This sweep covers every requested page and component. It deliberately does not restate the bug fixes in `desktop-appliance-audit-2026-08.md` or the state-model, intent fork, pairing, landing, and `LongOperation` work in `ux-journey-spec.md`. The jargon table is exhaustive because this brief explicitly requires every visible hit; where the sibling spec already owns the underlying change, the row points to its binding product wording rather than inventing a second solution.

Sizes mean: **S** = localized copy/style/ARIA change; **M** = component or screen-state refactor; **L** = shared pattern or cross-screen choreography.

### Shared composition rule

- [hierarchy][M] Browse/index screens (`Apps`, `Deployments`, `Cloud`) use `w-full max-w-5xl`; detail and management screens (`App`, `Environment`, `Deployment`, `Machine`, `Agents`, `Cloud detail`, `Settings`) use `w-full max-w-3xl`; focused setup/auth tasks use `mx-auto w-full max-w-2xl`, with actual forms capped at `max-w-lg`. All product screens use `text-xl` h1; focused setup/handoff screens may use `text-2xl`. Keep the title, one-sentence deck, and page actions in one header row before page-specific content. (`packages/app/src/components/layout/app-shell.tsx:107`, multiple page roots)
- [hierarchy][L] Put these rails in shared page-shell primitives instead of repeating width utilities. This resolves the current unbounded Apps/Deployments/detail pages, narrow `max-w-2xl` Settings/Doctor pages, and arbitrary `max-w-3xl` siblings without forcing dense browse grids into a detail-width column. (`packages/app/src/pages/apps/index.tsx:164`, `packages/app/src/pages/deployments/list.tsx:46`, `packages/app/src/pages/projects/detail.tsx:105`, `packages/app/src/pages/settings.tsx:26`)

## Voice definition

1. **Plain:** lead with the user outcome and use familiar nouns. Say **Sandbox**, **App hosting**, and **Set up hosting**; do not expose implementation names as product concepts.
2. **Honest about time:** state a useful duration before long work begins and say whether it is safe to leave the page. Never use vague reassurance such as “a moment” for work with a measurable shape.
3. **No jargon above the fold:** a new user should understand the title, deck, primary action, and first status without knowing Kubernetes, AWS internals, credential-broker terminology, or the CLI.
4. **Technical detail behind disclosures:** preserve diagnostic truth under a consistently named **Technical details** disclosure; errors lead with a plain headline and put raw output there too.
5. **Sentence case:** headings, labels, buttons, status text, and disclosures use sentence case. Avoid uppercase section furniture and engineering-state strings copied verbatim.

## Cross-screen interaction and accessibility contracts

- [a11y][L] Replace color-only state projection with **dot + persistent text label** everywhere: `● Healthy`, `◌ Deploying`, `× Failed`, `○ Not set up`. The text must be visible, not only an accessible name or tooltip. Reserve cyan for Sandbox capability/in progress and green for hosting-ready/success, as the sibling spec binds. Apply to app cards, environment/deployment rows, health summaries, run rows, cloud selection, terminal sessions, update results, policy decisions, and long operations. (`packages/app/src/components/ui/status-dot.tsx`, all consumers)
- [a11y][L] Adopt one true-black focus treatment for every interactive element: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-cyan-300 focus-visible:ring-offset-2 focus-visible:ring-offset-black`. Never remove outline without an equivalent ring. Apply to native buttons/links/inputs as well as shared `Button`; verify 3:1 focus-indicator contrast. (`packages/app/src/components/ui/button.tsx`, custom controls throughout audited files)
- [a11y][M] Changing single-line state uses `role="status" aria-live="polite" aria-atomic="true"`. Streaming logs use `role="log" aria-live="polite" aria-relevant="additions text"`, but batch announcements to one summary at most every 2 seconds; never read every build line. Failures use `role="alert"`; progress bars expose `role="progressbar"`, value, min, max, and an adjacent text percentage. (`packages/app/src/pages/bootstrap/progress.tsx:269`, `packages/app/src/pages/apps/deploy.tsx:1444`, `packages/app/src/pages/settings.tsx:170`)
- [interaction][M] Use inline error when the fix is on the current screen, the action can be retried there, or data may be lost; preserve it until the user changes the relevant field or retries. Use a toast only for completed background/global actions or success after the initiating surface disappears. Never put a raw server string in a toast; use `FriendlyError` inline with raw detail disclosed. (`packages/app/src/pages/settings-team.tsx:101`, `packages/app/src/pages/cloud/index.tsx:141`)
- [interaction][L] Destructive consistency: deleting a VM or app and removing a cloud connection use the standard dialog with object name, consequence, and specific verb; resetting firewall rules and forgetting credentials use an in-place two-step confirm because context must remain visible; destroying a cloud keeps type-the-name and then uses one final destructive dialog. Do not stack duplicate warnings in panel copy, name gate, and dialog. (`packages/app/src/pages/machine/runtime-detail.tsx:146`, `packages/app/src/pages/cloud/index.tsx:144`, `packages/app/src/pages/cloud/panels.tsx:930`, `packages/app/src/pages/machine/credentials-panel.tsx:172`)
